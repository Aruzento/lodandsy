# Стартовая задача Codex

Ты работаешь с существующим репозиторием LODANDSY, а не создаёшь новое приложение с нуля. Прочитай `AGENTS.md` и `docs/MVP.md`, README и существующие ADR/инструкции. Сверь реальные файлы, git status, HEAD, задачи Linear и результаты проверок. Сохрани текущий стек и имеющийся рабочий код там, где решение выдерживает критерии.

Цель — максимально быстро довести LODANDSY до проверяемого MVP. Работай крупными вертикальными блоками, не требуя моего подтверждения после каждой мелкой задачи. Не принимай неподтверждённые варианты из MVP.md за утверждённые продуктовые решения. Если есть доступ к первичному описанию продукта или архитектурным PDF, сверь их с контрактом. Если нет, сообщи об этом. Не переписывай проект без доказанной необходимости.

Сначала проверь baseline, сравни его с требованиями и составь короткую карту разрывов и последовательность функциональных блоков, привязанных к существующим ID Linear. В одном сообщении выдели только действительно важные решения владельца и рекомендуемые варианты. Не дублируй бэклог и не меняй статусы непроверенных задач.

Затем в этой же задаче начни и доведи до проверки первый независимый блок: защита Card/иерархии от обхода инвариантов, единый путь изменения/уведомления, индекс потомков и сохранение выбора/раскрытия Tree (сверь ARU-28–31). Если часть уже реализована, подтверди проверками и не переписывай. Добавь регрессионные тесты, выполни полный pytest и Ruff, покажи результаты. Параллельные независимые работы допустимы только при отсутствии конфликтов; не обещай непроверенных результатов. После этого продолжай следующий согласованный блок. Для спорной оконной модели и канонического хранения проведи прототипы и представь доказательства до необратимого выбора; не углубляй самописный docking без проверки альтернатив.

Порядок дальнейшей реализации: устойчивые документы и оконная модель → надёжное сохранение → завершённый Cards workflow → утверждённые Map и Tools → Windows-поставка и сквозная приёмка. Останавливайся только при реальном блокере или значимом решении владельца; не жди отдельного разрешения на каждую техническую правку.

Результат каждого блока: рабочий код, тесты, проверяемые пользовательские сценарии, фактические команды и результаты, объяснение рисков и состояния Linear. Не выдавай offscreen за проверку Windows. Не коммить и не пушь без моего разрешения.
