# Задача Codex — последовательная реализация следующей итерации LODANDSY

Требования пакета находятся в [docs/iterations/2026-11-19/REQUIREMENTS.md](docs/iterations/2026-11-19/REQUIREMENTS.md).
Неизменённая копия стартового документа из архива сохранена рядом с ними.

Тебе передаётся **единый объём работ**. Выполняй его **строго последовательно, функциональными блоками**. Не ограничивайся планом: после короткой проверки исходного состояния приступай к коду первого блока. Следующий блок начинай только после исправления ошибок, проверки предыдущего и обновления соответствующей задачи Linear. Если отдельный продуктовый вопрос не решён, фиксируй его и продолжай независимые части; не принимай молча решения, меняющие канонический формат данных или UX.

## Контекст

Исходная база: `Aruzento/lodandsy`, ветка `codex/mvp-cards-map-tools`, коммит для сравнения `409da1e1e7095117f70ee88ebc140ebe491d5d6b`. Сначала проверь **актуальный** `git status`, HEAD и рабочую ветку, не перезаписывай незакоммиченные изменения. `main` не изменять. Читай существующий `AGENTS.md`, `docs/MVP.md`, релевантные ADR и `REQUIREMENTS.md` из этого пакета. Референс архитектуры: модульный монолит Python 3.14/PySide6/Qt ADS, SQLite S3 + assets, Card Markdown E2 и ссылки по UUID. Прежний CI на указанном коммите проходил (196 тестов), но это не доказательство готовности новых функций. Чистая Windows без Python (ARU-64) ещё подлежит итоговой проверке.

## Цель

Получить не набор отдельных кнопок, а единый пригодный для повседневной работы продукт: карта и карточки создаются и открываются из дерева, Card имеет полноценную панель Markdown-разметки, изображения и шаблоны, а карта поддерживает большие растры, графические токены и настраиваемую сетку. Пользовательские данные и прежние проекты не теряются. Никаких заглушек, дублирующих путей сохранения и второго docking-движка.

## Порядок выполнения

1. **ARU-69** — единое дерево проекта Cards / Maps / Tables, контекстные меню и работающие кнопки возле узлов, быстрый доступ к Dice; открытие/фокусировка через ID и WindowManager. Верхние «Карты/Инструменты/Карточки» перестают быть главным способом навигации.
2. **ARU-72** — панель форматирования Card Editor: H1–H3, bold/italic/strike, цитаты, списки, код, разделитель, ссылки, клавиши и управление выделением; типографические стили и шрифты отображения. Markdown source/preview/split, undo/redo, курсор, scroll не ломаются. Не подменяй канонический Markdown HTML без утверждения.
3. **ARU-73** — вставка локальных изображений в карточки (выбор файла; по возможности clipboard/drop), безопасный импорт в assets, относительный Markdown и предпросмотр без сетевых ресурсов, сохранение и резервные копии.
4. **ARU-74** — выбор при создании Cards встроенного шаблона: пустая, статья, персонаж, локация, предмет (опционально заметки сессии). Это копируемые Markdown-заготовки, а не жёсткие игровые типы; существующие Cards не переписываются.
5. **ARU-70** — перейти от ограничения 16 млн пикселей и полного QPixmap к проверенному способу работы с крупными картами (производные тайлы, уровни детализации, асинхронный импорт, ограниченный кеш, безопасная отмена, измерения производительности). Сначала прототип/ADR, затем реализация; простое снятие лимита запрещено.
6. **ARU-71** — графические токены с файлами изображений, собственной геометрией/UUID и опциональной Card-ссылкой; квадратная карта-сетка с настройками, привязкой, хранением и Undo. Старые маркеры продолжают работать.
7. Полная регрессия, обновление документации и ADR, Windows-сборка/CI; подготовить сценарий чистой Windows для ARU-64. Не объявлять ARU-64 завершённой без фактического запуска на машине без Python.

## Обязательные критерии и отчёт

Смотри конкретные сценарии и границы в `REQUIREMENTS.md`. Каждый законченный блок должен иметь пользовательский сценарий, тесты (основной, невалидные данные, ошибки записи, повторное открытие, совместимость), обновлённую документацию при изменении поведения и соответствующее фактическое состояние Linear. Запусти `python -m pytest`, `python -m ruff check .`, `python -m pip check`; не выдавай незапущенные проверки за успешные. После блока пиши кратко: изменённые файлы, работающий сценарий, результаты команд, риски, что проверить вручную, состояние Linear, следующая задача. Не перепрыгивай к следующему блоку при регрессии и не исправляй её удалением теста.

Не делай commit/push/merge/release без моего прямого разрешения. Не создавай дубликаты задач в Linear: используются ARU-69/72/73/74/70/71 и ARU-64. Вопросы, которые меняют продукт/формат/стоимость, согласуй со мной. Остальное реализуй самостоятельно последовательно.
