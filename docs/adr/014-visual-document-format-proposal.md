# ADR-014 — единственный визуальный формат документа

Статус: принят владельцем. После первоначального принятия Qt HTML владелец отдельно
отменил legacy Markdown, обязательные миграции и архивирование. Это последнее решение
заменяет прежнюю политику per-Card conversion и сохранения старых source редакторов.
ARU-75, итерация 3; основной GUI/SQLite/Qt ADS/libvips стек сохраняется.

Контекст: нужен визуально редактируемый документ со шрифтом, размером, цветом,
выравниванием, списками, ссылками и изображениями. Markdown не выражает все эти свойства;
прототип подтвердил потери оформления при toMarkdown. Контролируемый Qt HTML сохраняет
проверяемую семантику. JSON block codec потребовал бы собственного преобразования всех
Qt структур без текущей продуктовой необходимости.

Решение:

- Единственный редактор Card — QTextEdit с защищённым QTextDocument, прямыми командами
  QTextCursor и сессионным Undo. Source/preview/split и прежний Markdown editor удаляются.
- Card payload v2: document {format: qt-richtext-html, version: 1, html: ...}, portrait: null
  или типизированный портрет из C. ID/title/parent/order принадлежат общему Entity.
- Один canonical SQLite проект S3, общий revision/save pipeline. Никаких legacy payload,
  архивов исходника и двух редактируемых редакций. Новые проекты создаются сразу в
  актуальной схеме; старые версии отклоняются без изменения БД. Тестовые миры пересоздаются.
- Единственный публичный URI: lodandsy://entity/UUID. Kind разрешается по реестру текущего
  проекта. card/UUID и прочие старые схемы не поддерживаются. Переход через application
  layer/WindowManager; исходный документ остаётся открытым, missing target диагностируется.
  Копирование ссылки даёт безопасный HTML fragment и plain URI; название независимо от ID.
- Whitelist структур/атрибутов/CSS, бюджеты размера/nodes/depth, очистка clipboard. Assets
  только внутри проекта, bounded decoder/cache; document-level loader возвращает валидный
  sentinel и не вызывает Qt filesystem fallback. HTTP/HTTPS — только по явной активации;
  остальные URI и сетевые ресурсы блокируются. Нет web runtime и пользовательского кода.
- App-owned qrichtext header и фиксированные whitespace правила сохраняют вложенные списки.
  Произвольные head/CSS удаляются. HTML нормализуется; контрактом служит семантика, не
  побайтовое совпадение Qt сериализации. Просмотр/масштаб/диагностика ссылок не меняют данные.
- Один QTextDocument на Card в сессии. Сигналы собственного ввода не вызывают повторный
  setHtml. Прямые операции, close/reopen, thumbnail updates сохраняют Undo и контекст.

Общее правило разработки по последнему указанию владельца: не сохранять устаревшее
решение без обоснованной необходимости. Удалять заменённые редакторы, модели, форматы,
режимы и адаптеры; не добавлять миграции/архивирование только ради тестовых данных.
Исторические ADR и отчёты остаются историей, а не разрешением поддерживать старый код.
Пользовательские файлы автоматически не удаляются и не перезаписываются.

Проверки: production semantic/security/UI/save/reopen/backup tests и общий набор,
Windows smoke и итоговая ручная приёмка G. Ранее прототип проверил 13 corpus cases:
12 сохранили проверяемую HTML семантику; нестандартные Markdown metadata терялись —
поддержка их конвертации теперь прямо отменена владельцем. Прототип и legacy fixtures
не нужны production пути и удаляются. Реальный Windows capture ранее дважды timeout;
скриншот/ручная DPI приёмка этим не заявлялись.

Источники API: https://doc.qt.io/qt-6.11/richtext-html-subset.html,
https://doc.qt.io/qt-6.11/qtextdocument.html, https://doc.qt.io/qt-6.11/qtextedit.html.
Проверяется pinned PySide6/Qt 6.11.2. Пересмотр при объективной потребности в сложном
block editor либо изменении Qt. Новая зависимость/другой публичный формат согласуются.
