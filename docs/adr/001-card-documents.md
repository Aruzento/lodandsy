# ADR-001: карточки и независимые документы

Статус: принят в части политики документов владельцем 18.11.2026 в чате;
локальная реализация проверена автоматически, ручная приёмка Windows остаётся открытой.
Связанные задачи: ARU-28–31, ARU-33, ARU-58.

Контекст: изменяемый Card позволял обходить доменные проверки; Tree, Inspector и Editor
записывали изменения разными путями. Единственный редактор переназначался при выборе
карточки, setPlainText сбрасывал историю редактирования.

Варианты: защищённые изменяемые объекты или неизменяемые снимки; один редактор,
следующий за выбором, или независимые документы по ID. Владелец подтвердил второй
вариант документов. Для данных выбраны frozen dataclass со slots: это локальный
внутренний контракт, публичный формат хранения ещё не существует.

Решение:

- CardCollection владеет текущими снимками Card и индексом parent → child IDs.
  Полученный ранее Card не обновляется на месте; актуальное состояние читается по ID.
  UUID, title/content и иерархия валидируются вне Qt; составная правка проверяется
  полностью до изменения коллекции и индекса. Заголовок обрезается по краям,
  пустой заголовок запрещён, содержимое не нормализуется.
- UI-команды проходят через ApplicationSession.create_card/update_card/delete_card.
  Уведомления содержат ID и изменённые поля; неизменившаяся или отклонённая правка
  уведомления не создаёт. Доменная коллекция остаётся самостоятельным объектом без Qt.
- Выбранный ID принадлежит Session; активный ключ рабочего окна — WindowManager.
  Документ привязан к собственному card_id и не зависит от выбора в Tree.
  Повторное открытие ID фокусирует существующее окно. Inspector следует за Tree.
- WindowManager владеет registry и закрытием окон. AppController связывает редакторы
  с карточками и освобождает bindings при закрытии. Удаление поддерева закрывает
  только документы удалённых ID; запоздалый close старого окна не затрагивает новое.
- QTextDocument, Undo/Redo, выделение и прокрутка — локальное состояние представления,
  сохраняемое в течение сессии, включая close/reopen. Оно не является вторым хранилищем
  мира: любая правка редактора синхронно проходит через Session и CardCollection.
  Закрытый документ получает внешние изменения через тот же ID.
- Tree сохраняет выбор/раскрытие при структурном rebuild, rename обновляет одну строку,
  content не перестраивает Tree. Выбор Session отражается в Tree без повторной команды.

Доказательства: регрессии в test_card_invariants.py, test_card_change_integration.py,
test_card_editor_window.py и test_document_lifecycle.py; полный набор и ограничения
описаны в ../validation/2026-11-18.md.

Ограничения: хранение мира и восстановление UI между запусками не реализованы;
существующий CENTER/docking требует отдельного решения ADR-002. Qt-представления
работают в GUI-потоке. Сохранение истории после выхода и несколько окон одного ID
не обещаны. Пересмотреть документ при принятии другого UX документов или необходимости
совместного редактирования одной карточки в нескольких окнах.
