# LODANDSY — текущий контракт MVP и итерации 3

Локальная нативная среда ведущего: несколько документов, карты и инструменты сосуществуют
и надёжно сохраняются. План/статусы — Linear, архитектура — ADR, проверки — docs/validation.
Указания владельца имеют приоритет над историческими требованиями архива.

## Общее правило разработки и хранения

Последнее решение владельца отменяет обратную совместимость тестовых данных, legacy
Markdown, старые редакторы/режимы/форматы/адаптеры. Только визуальный Card ADR-014 и URI
lodandsy://entity/UUID. Обязательные миграции и архивирование source не нужны. Устаревшее
решение сохраняется только при обоснованной текущей необходимости. Старые файлы не
удаляются автоматически: неподдерживаемая версия отклоняется без записи.

S3: одна SQLite через sqlite3 без ORM; UUID стабильны, assets отдельно с относительными
путями, foreign keys на каждом соединении. Составные операции транзакционны; один
autosave/Ctrl+S pipeline: dirty/saving/error, порядок ревизий, безопасное закрытие,
backup/restore. Неизвестные kind/payload/schema не переписываются. Домен без SQL/Qt.
Поиск и tile cache производные. Backup до4GiB без tile cache.

## A — канонические сущности и дерево (ARU-34…39)

Entity: id/kind/title/parent_id/position, payload модуля отдельно. Смешанный лес
Card/Map/Table/DiceDocument без групп. Родитель существует или отсутствует, циклы/дубликаты/
невалидный порядок запрещены доменом. DnD между любыми типами, root drop, Inspector,
удаление поддерева с подтверждением. Ссылки не смешиваются с иерархией.
Выбор Tree, открытый документ, активное окно и UI state независимы. Адресные события по ID.
Плюс с меню создания, скрытый поиск, создание дочернего через context.

## B — визуальный документ (ARU-75, ADR-014)

QTextEdit/QTextDocument, контролируемый Qt HTML Card payload v2. Шрифт/размер/цвет,
B/I/U/strike, выравнивание, заголовки, списки, цитата/код, ссылки, локальные изображения,
Undo/Redo. Один документ на ID в сессии; close/reopen сохраняет Undo/курсор/прокрутку/масштаб.
Просмотр/масштаб/диагностика не меняют содержимое. Копирование ссылки: HTML fragment и URI.
entity/UUID разрешается в текущем проекте через application layer, открывает/фокусирует
цель, исходник остаётся; подпись независима от названия, битая цель диагностируется.
HTTP/HTTPS только по явной активации в браузере. Сетевые ресурсы/иные URI блокируются.
Assets loader ограничен директорией проекта, bounded decoder/cache и placeholder.
Вставка очищается whitelist с бюджетами размера/глубины/узлов.

## C — портрет и шаблоны (ARU-76)

Шаблоны Пустая/Статья/Персонаж/Локация/Предмет копируются один раз при создании.
Персонаж — Card со свободным текстом, без RPG-модели. Typed portrait asset reference,
alt/необязательная подпись: выбрать/заменить/убрать, aspect fit/placeholder. Inline images
независимы. Общие assets не удаляются вместе со ссылкой.

## D — единые токены и сетка (ARU-77)

Один Token вместо MapPin/прежнего токена: UUID/имя/kind character или item/image asset/
ссылка entity_id/footprint в клетках. Character круглый с белой рамкой; item aspect fit
с alpha без рамки. По умолчанию1×1, поддерживается2×2 и больше. Видимая мировая сетка,
шаг/offset/цвет/opacity/snap; pan/zoom не меняют геометрию. Удалённая цель сохраняет
токен с разорванной ссылкой. Per-map Undo, независимые окна и libvips tiles сохраняются.

## E — таблицы (ARU-78)

Многоколоночный документ: UUID колонок/строк, имена/порядок/типы text/number/bool,
ячейки по ID колонок, редактирование/перестановка/удаление/копирование. QTableView/model,
без QWidget на каждую ячейку. Выбор целой непустой строки; 0 и false — данные.
Сохранение/перезапуск/backup через общий pipeline.

## F — визуальные кубики (ARU-79)

Счётчики d4/d6/d8/d10/d12/d20/d100, модификатор, смешанный бросок, каждый результат и сумма.
Именованные UUID DiceDocument с сохранёнными пресетами, повтор/копирование. RNG инъецируется,
без eval. Бросок не dirty world, конфигурация сохраняется общим pipeline.

## Окна, границы и G — приёмка

Python3.14/PySide6/Qt Widgets, модульный монолит domain/application/ui. Qt ADS5.1.1 /
PySide6 6.11.2: ADS размещает, WindowManager управляет жизнью. Tree/Inspector/rails фиксированы.
Одновременно разные Cards/Map/Table/Dice, один редактор ID. Layout/выбор/камера отдельно.
Проверить focus/dock/insert/center/float/redock/maximize→drag/мониторы/DPI.

Большие изображения остаются на ADR-011: ограниченный отдельный libvips worker, SHA/version
проверяемая пирамида, атомарная публикация, progress/cancel/rebuild. Реальные большие файлы/
несколько карт/сбой/повторное открытие. Запрещено снимать лимит полным декодированием в GUI.
Вне границ: fog/lighting/multiplayer/боевые правила/сервер/облако/web runtime/SDK/автообновления/
сложные игровые модели.

После A–F: целевые/полные тесты, Ruff/pip, docs/ADR/Linear. G (ARU-63/64) — Windows ZIP и
чек-лист десяти замечаний пакета. Ручные Windows сценарии и запуск полной новой сборки без
Python обязательны; offscreen/smoke не заменяют их. Не отмечать Done без нужной проверки.
Commit/push/merge/release только по отдельному разрешению.
