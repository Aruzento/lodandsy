# Управление проектами · кандидат LODANDSY v0.01

26.11.2026, ARU-44, ARU-53, ARU-54 и ARU-66. Рабочее дерево ветки
`codex/tools-t3` поверх `ffa1dc2` включает принятые визуальные исправления.
Поставка предназначена для проверки первого кандидата с контрактом совместимости.

## Реализация

| Компонент | Поведение |
|---|---|
| `application/project_catalogue.py` | Один управляемый корень из Qt DocumentsLocation. Обнаружение прямых каталогов с признаками мира, проверка имён и пути, регистронезависимая коллизия и защита параллельного создания. |
| `application/project_controller.py` | Общий прикладной путь и прежние guards. После успешной проверки новый мир получает управление и прежний writer lock освобождается. Неудачное переключение сохраняет открытый мир и черновики. |
| `application/sqlite_project_store.py` | Новый мир собирается во временной соседней папке и публикуется без перезаписи. Сканирование читает существующую БД. Несовместимая SQLite-схема отклоняется до блокировки на запись. Restore использует прежний контейнер и проверяет свободное место перед распаковкой. |
| `ui/project_chooser.py`, `ui/project_name_dialog.py` | Welcome и Open показывают найденные миры, время открытия по локальной истории, диагностику и явную команду внешнего открытия. Нативный диалог имени показывает путь и оставляет поле доступным при отказе. |

Папка определяется при запуске через системный путь к Documents и создаётся
при первой операции записи. Ограничение длины полного пути составляет 200
единиц UTF-16, чтобы оставить запас для служебных файлов в Windows. Имена
с внутренним префиксом `.lodandsy-` зарезервированы. Произвольные папки без
файла БД или маркера проекта не попадают в список. Повреждённый и несовместимый
мир остаются видимыми с диагнозом. На старте мир не открывается автоматически.
Дата открытия берётся из истории LODANDSY. Для ранее неизвестного мира она
остаётся неизвестной до первого успешного открытия.

При восстановлении начальный вариант имени берётся из названия архива. Можно
ввести любой допустимый свободный вариант. Восстановленный проект сохраняет
UUID и данные исходного мира, сам архив и существующие папки остаются на месте.
Сканирование выполняет локальное чтение БД и валидацию ссылок. Полное чтение
и проверка хешей файлов вложений выполняются во время восстановления. Каталог
и восстановление работают синхронно.

## Совместимость с v0.01

Запуск `python -m lodandsy.main --version` сообщает `LODANDSY v0.01`.
Упаковочные метаданные Python — `0.1.0`. Базовые версии мира: SQLite17,
Card8, Map9, Actor1, Rules1 / D&D 5e 2014 profile2, Table4, Economy1.
Раскладка остаётся отдельным файлом формата 4. Расположение проектов и
обозначение приложения не меняют формат. Перенос на месте и миграция здесь
не требуются. Поддерживаемые миры защищены обязательным контрактом будущих
миграций, бэкапа и отката. [ADR-040](../adr/040-managed-projects-v001.md)

Синтетический мир создан кодом предыдущего ZIP Tools T3 / UI System и дважды
открыт кандидатом v0.01. Версии прочитаны непосредственно из SQLite. Контрольные
суммы БД, ресурсов и служебных файлов совпали до и после обоих открытий.
[Проверенные версии и повторное открытие](2026-11-26-managed-projects/format-baseline.json)

## Проверки

| Сценарий | Свидетельство |
|---|---|
| Первый запуск и перенаправленный Documents | Каталог отсутствует до записи. Qt resolver замещён временным системным путём в тесте. Диалог по имени публикует мир в правильной папке. |
| Имена и параллельное создание | Кириллица, пробелы, Unicode, DOS reserved names, разделители, `..`, длина, контрольные символы и регистр. Две попытки создания с разным регистром дают один мир. |
| Недостаток прав и места | Инъекции EACCES и ENOSPC при создании, предзапусковая проверка свободного места при восстановлении. Текущий мир и данные сохранены, staging очищен. |
| Каталог независимо от истории | Обнаружение известных и неизвестных миров, фильтрация произвольной папки, диагностика повреждения и будущей схемы, открытие через Welcome. |

| Совместимость | Для SQLite1–16, 18 и 999 проверены отказ и совпадение контрольной суммы БД. У будущей схемы не создаётся writer lock. |

## Чек-лист ручной приёмки

Выполнять на чистой Windows в тестовом профиле или с отдельными тестовыми
мирами. Проверки нехватки места и неподдерживаемой версии проводить на копиях.

- [ ] На первом запуске виден пустой каталог. «Создать проект» открывает компактный диалог.
- [ ] Ввести «Этар и окрестности», проверить полный путь, создать и сохранить карточку.
- [ ] Повторить имя в другом регистре, проверить подсказку и сохранность первого мира.
- [ ] Перезапустить EXE. Видны созданные миры и известное время открытия. Мир не открывается сам.
- [ ] Открыть совместимый мир вне каталога через «Открыть другую папку». Проверить, что его папка осталась на месте.
- [ ] Попытаться открыть недоступный мир при несохранённом вводе. Проверить открытый мир, активный документ и черновик.
- [ ] Запустить второй экземпляр и проверить отказ одновременной записи. Закрыть первый экземпляр и открыть мир во втором.
- [ ] В настройках создать backup, восстановить под новым названием и сравнить карточки, карту, ресурсы и кошелёк.
- [ ] Проверить в перенаправленном Documents путь нового мира и повторное обнаружение.
- [ ] Проверить архив на отдельной Windows без установленного Python.
