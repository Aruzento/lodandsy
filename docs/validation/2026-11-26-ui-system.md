# ARU-26 · Визуальный стандарт и полировка Tools T3

26.11.2026, кандидат поверх `ffa1dc2`, ветка `codex/tools-t3`.
Связанные задачи ARU-79 и ARU-92–96 остаются в работе до ручной приёмки.
Платформа проверки Windows 10 x64, Python 3.14.8, PySide6 6.11.2, Qt ADS 5.1.1.

## Что изменилось

- `ui/theme.py` и `ui/icons.py` задают роли палитры, шрифт, нативные состояния,
  размеры управляющих элементов, SVG и оформление ADS. Tree и Inspector используют
  общую тему. Лист, Card Editor и принятая панель карты сохраняют свои размеры.
  [Визуальный стандарт](../design/UI-SYSTEM.md)
- `SettingsDialog` объединяет правила, валюты, категории и операции с данными.
  Шестерёнка активирует существующее окно. Редакторы правил и экономики сохраняют
  свои черновики при переходе между разделами. Смена мира с несохранёнными
  параметрами требует явного решения. Backup/restore запускаются отдельными командами.
- `AppendHeader` использует одинаковые 30×30 px SVG-кнопки. Таблица резервирует
  место после секций в обоих направлениях. `WalletWidget` редактирует точные
  целочисленные количества через общий `FieldEdits` по адресу таблица + номинал.
  Enter, Tab и потеря фокуса подтверждают число. Escape отменяет текущий ввод.
  Неверное число можно исправить или сбросить. Конфликт проверяется по канону.
- Кубики адаптируют сетку к ширине и используют SVG для изменения количества,
  очистки, повтора и копирования. Лут и магазин используют единые параметры,
  таблицу, диагностику и итог. В луте базовый номинал виден рядом с денежными
  диапазонами при заполненных значениях. Item выравнивает поля стоимости и категории
  с основной формой. Welcome сообщает, как начать работу при пустом каталоге.
- ARU-95. Поиск в глубину начинал с многократного выбора первого случайно
  упорядоченного Item. При равных ценах всегда срабатывал этот путь. Теперь перед
  обходом выполняется одна ограниченная случайная проба набора с возвращением
  на каждое число единиц. Общая проверка стоимости и монет применяется к обоим
  путям. Полный обход в пределах лимита сохраняет различие между доказанно
  недостижимым условием и исчерпанием поиска. Детерминированный тест выполняет
  100 прогонов с десятью равноценными Item и проверяет разнообразие, допустимость
  повторов и обязательный повтор в пуле с единственным Item.

Рабочие модели и сохранение остались на SQLite17 / Card8 / Table4. Раскладка,
Actor, сессия и транзакционный путь не менялись. Выбор компоновки в настройках
следует существующим разделам. У приложения сейчас нет отдельных общих настроек
или настроек интерфейса, поэтому для них не добавлены пустые страницы.

Учётная запись Windows не имеет права создавать symlink для одного теста
безопасности путей. Offscreen дополнительно пропускает сценарий активации Player.
На Windows QPA сценарий активации выполнен.

Ручная приёмка владельцем включает пользовательскую оценку контраста и фокуса,
перетаскивание и стыковку между мониторами с разным системным DPI,
maximize/restore и запуск на отдельной чистой Windows.
