# ARU-77 и ARU-93 — инвентарь участника из меню токена

26.11.2026. Кандидат LODANDSY v0.01 для архитектурного аудита.

## Поведение

В контекстном меню токена в игровом окне карты пункт «Открыть инвентарь» имеет
SVG-иконку и доступен для участника с индивидуальным инвентарём. Окно
«Инвентарь — [имя участника]» использует существующий редактор Table с кошельком,
экипировкой, ссылками на карточки Item и вставкой лута. Повторная команда
фокусирует это окно. Если таблица уже открыта во вкладке, она становится плавающей
и сохраняет текущее представление.

Игровые токены общего Actor используют один UUID таблицы. Два NPC одной
карточки сохраняют независимые инвентари. Удаление Actor закрывает его таблицу.
Смена проекта закрывает документы предыдущего проекта. При повторном открытии
восстанавливается сохранённая раскладка мира.

## Архитектурные компоненты

| Владелец | Изменение |
| --- | --- |
| Maps | `map_widget` использует каноническую проекцию участника для доступности команды. `map_annotations` показывает действие, `maps_controller` разрешает актуальное размещение и передаёт идентификаторы Card и Actor. |
| Composition root | `app_controller` разрешает `Actor.inventory_id` в текущей сессии и формирует заголовок окна. При переименовании обновляет только окно нужного инвентаря. |
| Tables | `tables_controller` открывает существующую таблицу и подписывает её представления на прежние уведомления. |
| Workspace | `window_manager` использует стандартное плавающее размещение Qt ADS и фокусирует существующее окно. `icons` хранит SVG команды. |

Форматы SQLite17, Actor1, Table4 и раскладки v4 сохранены. Операции с
экипировкой, кошельком, черновиками и вставкой используют действующий
транзакционный путь. [ADR-039](../adr/039-tools-t3-economy-inventory.md)

## Целевые проверки

`tests/test_map_token_inventory.py` проверяет меню, SVG, повторный фокус,
перевод существующей вкладки в плавающее окно, отсутствие инвентаря, удаление
Actor, разные кошельки NPC и общий инвентарь Player на двух картах.
В том же наборе проверены типизированная вставка лута, ссылка на Item, экипировка
и её влияние на КД, синхронное обновление двух представлений таблицы, запись
в SQLite, смена мира и восстановление окна и данных.

Целевой набор вместе с тестами контекстного меню, Qt ADS и архитектурными
проверками — 28 прошли.
