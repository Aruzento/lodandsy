## Цель и неизменяемый контракт

Нативный local-first модульный монолит Python 3.14/PySide6 Qt Widgets, Qt ADS, SQLite S3 + assets, libvips и перестраиваемые пирамиды; единая иерархия Entity Card/Map/Table, один UUID и один canonical title. Card type-only без templates/tags; aliases скрыты и доступны поиску; один канон портрета, typed fields, richtext Qt HTML с локальной безопасностью; динамические section UUID и дочерние Table refs; Card→0..N TokenInstance; Tools/Dice вне Entity, один tool:dice; отдельные Map Viewer и Map Editor. Не возвращать удалённые функции. Приложение должно оставаться функциональным при закрытых других представлениях. Сохранить DnD, docking/float, layout, undo, безопасный import MOW, актуальные save/backup/reopen.

Согласованные события ID + изменённые поля; редактирование одной карточки не перезагружает все карты/таблицы. Нормальные явные связи данных (предмет→inventory, card→token) полезны, их не устранять.

## B. Инвентарь и универсальные ссылки/проекции (ARU-83/78/80)

Требование владельца: Предмет | Количество | Описание | Стоимость. Текущий ApplicationSession.section_table создаёт только 3 колонки (text/number/text); ColumnDefinition поддерживает text, number, bool. Новый инвентарь — обычная дочерняя Table entity, а не отдельный Inventory store. Существующий принцип создания ровно один раз сохраняется.

Расширить универсальный тип поля колонки до entity_ref с указанием допустимого kind/card_type и derived field projection (ID колонки ссылки + стабильный field key). Не реализовывать произвольную формульную DSL. Для inventory связанный предмет = UUID любого Card типа item в текущем проекте, а не только ребёнок персонажа. Количество = положительное целое, значение по умолчанию 1 при добавлении новой записи. Описание — summary предмета, если пустое — безопасная краткая plain-text проекция его description; полное описание открывается в Card. Стоимость — текущая единичная cost Card (без умножения), если не задана — «—», не 0; валюта/экономика и итоги вне scope. Описание и стоимость read-only derived, не записывать копии в строки. Колонки определяются стабильными ключами/UUID, не локализованным заголовком. Пользователь может создавать обычные столбцы и другие таблицы; зависимые проекции при удалении source column корректно диагностируются или удаляются явно, без молчаливой неконсистентности. Количество остаётся при замене предмета. Разрешены несколько строк с одним предметом (не объединять молча). Никаких механик экипировки/веса/переноса между персонажами.

Селектор предмета открывается из ячейки: поисковая строка с немедленной фильтрацией по title/aliases, только item, различать одноимённые по пути в дереве (или UUID в tooltip); keyboard navigation, Escape отменяет, Enter выбирает, поиск масштабируется до 10 тыс. предметов (model/view, индекс или debounce; не 10k widget instances). Ссылка позволяет открыть карточку отдельно; удаление строки не удаляет предмет. Переименование/стоимость/описание/смена типа/удаление предмета отражаются без повторного открытия Card/Table; если цель исчезла или перестала быть item, сохранить UUID и количество, показать «Предмет недоступен» и дать выбрать другой; без тихого каскада inventory rows. Не мешать существующему отдельно согласованному cascade tokens. Недопустимая ссылка при вводе/TSV диагностируется, импорт/сохранение не создаёт выдуманных Card IDs; поведение copy/paste для ссылок и read-only колонок задокументировать. Изменение карточки должно отражаться в embedded и standalone Table, закрытом и заново открытом представлении. Версионировать payload/schema, не поддерживать промежуточные форматы; MOW import адаптировать к актуальному контракту без выдуманных значений.

Проверки: exact columns/defaults, complete/empty rows, 0/negative/non-integer/invalid count, type filter, alias/search/одноимённые, rename/change cost & description incl empty vs 0, remove/change card type, reassign, duplicate row, two views, save/reopen/backup, project switch, large-item search benchmark vs real scale. Общая модель таблиц остаётся масштабируемой, не добавлять N+1 resolution при каждом paint. Использовать ID-index и адресное обновление затронутых строк.

## D. Точечные дефекты и долгосрочные ограничения (ARU-75/33/46/54/45/78/81)

(2) CardCollection.create(sections=...) с дефолтным content=EMPTY_DOCUMENT отвергает оба аргумента; сделать однозначную ветку/sentinel, проверить explicit sections/custom sections и default creation. ### A/B/D — редактирование и сохранение (ARU-84/78/83/46)

Подтверждено в коде: LiveCellDelegate.createEditor подключает textEdited → model.setData на каждый символ; ModuleSession.update_table публикует table_changed, ModuleController._refresh_table обновляет все TableWidget и _refresh_embedded_links пересобирает Card через set_canonical. SaveCoordinator уже имеет debounce 750ms. Это вероятный источник остановки ввода; сама потеря фокуса пока подтверждена ручным сообщением владельца, а не новым запуском ChatGPT. Сначала воспроизвести реальной последовательностью клавиш с двумя представлениями одной Table. Устранить feedback loop, не ограничиваться увеличением timeout.

- Черновик редактирования хранится на время действия по table/row/column UUID или card/field key; активный редактор, его текст, курсор, выделение и undo не перезаписываются входящими событиями. Строки/столбцы не переидентифицировать по индексу после изменения порядка.
- Для обычной ячейки/структурированного поля — один валидированный semantic commit при Enter/Tab/уходе из редактора; Escape отменяет. Checkbox и выбор сущности — одно завершённое действие, вставка диапазона атомарна. Не публиковать частично набранное слово в другие окна. Уведомлять их адресно после commit, не пересобирать Card Editor на изменение ячейки. Обрабатывать удаление строки/столбца и конфликт другого представления без silent overwrite.
