# Промпт для Codex — LODANDSY, итерация 3

Ты продолжаешь нативное Windows-приложение LODANDSY в существующем репозитории `Aruzento/lodandsy`. Последняя проверенная при подготовке задания ветка `codex/mvp-cards-map-tools`, commit `1835e3b`; перед работой проверь актуальный HEAD и git status. Не изменяй main.

Прочитай `AGENTS.md`, `docs/MVP.md`, существующие ADR, `REQUIREMENTS.md` этой итерации, код, тесты и связанные задачи Linear. REQUIREMENTS содержит все 10 замечаний владельца после ручной проверки и полный новый контракт. При расхождении с прежним MVP зафиксируй изменение требований, не скрывай конфликт. Это один пакет задач; выполняй его последовательно, а не только составляй план.

Порядок:

A. ARU-34/35/36/37/38/39 — единый Entity envelope, смешанная иерархия Card/Map/Table/DiceDocument, убрать искусственные группы дерева и безопасно мигрировать данные. Существующая ARU-69 отражает старый UX, не создавай дубликат.
B. ARU-75 — визуальный редактируемый rich-text документ, не Markdown source и не read-only preview. Предпочтительный прототип QTextEdit + контролируемый HTML subset; сравни альтернативы и проверь round-trip наследуемых документов. Согласуй новый публичный формат/миграцию одним архитектурным вопросом до production conversion; предложи конкретное решение, не запрашивай подтверждения технических мелочей.
C. ARU-76 — отдельный портретный блок персонажа, визуальные шаблоны, общие assets.
D. ARU-77 — видимая настраиваемая сетка, один тип размещаемого объекта Token вместо Marker, два вида токенов (персонаж: круг + белая рамка; предмет: оригинальная форма без рамки), 1×1 клетка для обычного токена и расширяемый footprint. Сохрани исходные данные и координаты, libvips и тайлы.
E. ARU-78 — полноценные многоколоночные таблицы, типизированная схема, стабильные ID, случайная запись и безопасная миграция прежних строк.
F. ARU-79 — пользовательские заготовки кубиков, визуальный выбор количества по видам, смешанный бросок, отдельные результаты и итог, сохранение.
G. Общая проверка, Windows-дистрибутив и обязательная чистая Windows без Python (ARU-63/64). Проверь весь комплекс 10 замечаний, предоставь владельцу ZIP и сценарии ручной проверки.

Начни с A. Сохраняй архитектуру модульного монолита, S3 SQLite + assets, существующие UUID, Qt ADS/WindowManager и libvips. Не добавляй двойной формат данных, новый GUI-стек, VTT gameplay или преждевременную платформу баз данных. Любым миграциям — резервная копия, восстановление, проверка реальных старых проектов и отсутствие потерь. У старого формата нельзя отнимать доступ к содержимому без безопасного перехода. Не выполняй скрытую замену старых маркеров или форматирования.

На каждом блоке: проверь его критерии из REQUIREMENTS; реализуй рабочее поведение, тесты, устрани вызванные изменениям регрессии, проведи целевые и общие проверки, обнови ADR/MVP при изменении контракта, Linear и кратко отчитайся. Переходи к следующему блоку только после выполнения необходимых проверок; при существенном продуктовом/архитектурном решении или обязательной ручной проверке обозначь точный блокер. Не отмечай Done без подтверждения критериев. Не утверждай, что был ручной Windows тест, если его не проводил. Не повторяй уже проверенную работу.

В отчёте: Linear ID, изменения, фактические команды/результаты, проверенные миграции и риски, что не проверено, следующий блок. Запланируй итоговый Windows ZIP и реальные скриншоты, но не отправляй пользовательские данные и сборки в Git. Commit/push/merge/release только после моего разрешения. До этого не трогай main.

Начинай реализацию блока A, не ограничивайся ответом с планом.
