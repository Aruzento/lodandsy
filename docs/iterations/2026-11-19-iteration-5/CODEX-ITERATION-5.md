## A. Упростить модель Card и общую иерархию
**Linear:** ARU-80, ARU-34–39, ARU-75, ARU-76, ARU-65. Пункты владельца 1, 2, 4, 5; аудит 1–2.

- Единственный продуктовый выбор — `card_type`. Удалить `template_id`, `TemplateDefinition`, каталог самостоятельных шаблонов, выбор шаблона при создании и в редакторе, template-specific storage/код. CardTypeDefinition определяет начальные вкладки, подходящие поля, представление и default token kind. Статья/персонаж/предмет/локация/остальные существующие типы остаются. При смене типа не стирать уже созданные вкладки/поля молча; показывать применимые поля, сохранить введённые значения при смене типа. Без отдельного конструктора типов.
- `Entity.title` — единственное название; summary и rich-text данные не дублируются. Типизированные характеристики (HP, AC, скорость и т.д.) редактируются только в Inspector. Убрать группу «Характеристики» и соответствующие кнопки из тела карточки. Inspector использует общий API; не создавать второй набор values. Доступ к будущим игровым переменным не зависит от UI.
- Aliases сохранить в данных и импорте для будущего wiki-link resolver; не показывать в шапке карточки. Сейчас отдельный UI редактирования aliases не требуется. Tags удалить из Card, FieldDefinition, поиска, форм, кодеков, MOW mapping и актуальных тестов. Не переиспользовать tags как скрытый источник навигации.
- Исправить аудит: выбор «Добавить поле» предлагает только допустимые отсутствующие поля; повторное добавление существующего — отказ/no-op, никогда reset заполненного значения. Весь путь, включая domain/service, защищён. Устранить недостижимые ветки `Card.value/with_fields` для portrait (реализовать согласованный типизированный доступ/обновление или выделить явный публичный media contract без мёртвых веток). Portrait — один источник истины, не второй asset ID в values.
- Tree сохраняет смешанную иерархию Card, Map, Table и стабильный Entity envelope. Dice перестаёт быть entity (блок F). Обновить схему SQLite и версии payload до нового единственного формата, не строить постоянные миграторы промежуточных тестовых схем.

**Приёмка:** создать карточку каждого базового типа без выбора шаблона; сменить тип без потери содержания; в Card нет характеристик, aliases и tags; Inspector меняет те же поля, которые видит токен. Повторное добавление HP не меняет 15 на default. Сохранение и повторное открытие нового формата, отказ старого без записи, проверки домена/сессии/кодеков.

## B. Вкладки карточки и вложенные таблицы
**Linear:** ARU-83, ARU-75, ARU-76, ARU-78, ARU-33. Пункты 3, 7.

Сделай вкладки настоящими настраиваемыми разделами. Начальный набор задаёт тип при создании, а не шаблон. `CardSection`/эквивалент: стабильный UUID, название, порядок, вид (rich_text или table_ref), содержимое rich text либо UUID существующей Table. Не строить ключ хранения/связь из отображаемого названия. Каноническое описание хранится один раз, а не одновременно в Card.content и новом разделе. [+] справа от вкладок открывает создание текстовой вкладки или дочерней таблицы (для таблицы можно выбрать существующего дочернего Table); ПКМ — переименовать, удалить с подтверждением, при необходимости изменить порядок. При rename не сбрасывать Undo, scroll и draft. Обновление UI адресное; не пересоздавать все вкладки/документы на каждое нажатие клавиши. Сохранить отдельное состояние QTextDocument/Undo/cursor каждой rich-text вкладки; закрыть/открыть и сменить вкладку корректно. Активная вкладка — UI state, не новый канон.

«Инвентарь» персонажа — дочерняя Table, а не rich-text имитация. При первом обращении к новому инвентарю создать дочернюю таблицу ровно один раз через атомарную операцию, связать её UUID с вкладкой, показать нормальный табличный интерфейс. До первой активации допустима явная кнопка создания, не создавать сущности при каждой отрисовке. Минимальные столбцы для нового инвентаря: «Предмет» (текст), «Количество» (число), «Описание» (текст); без расчёта веса/правил. Tree показывает этот Table как ребёнка Card. Его можно открыть в отдельном окне и редактировать с обеих поверхностей: одна таблица, общий ModuleSession, одинаковые данные и draft state. Переиспользовать виджет/модель таблиц из E, не копировать содержимое в Card HTML. Переименование вкладки не создаёт новый Table и не обязано переименовывать сущность; переименование таблицы не меняет UUID ссылки. Удаление вкладки-ссылки не удаляет таблицу. Удаление или перемещение дочерней таблицы обрабатывать явно: показать недоступную связь или предложить убрать её/заменить, без выдуманного нового документа и дублей. Поддержать повторный импорт/backup/restore новых связей.

**Приёмка:** [+] -> текст -> rename через ПКМ -> edit -> Undo -> reopen; два разных раздела независимы. «Инвентарь» создаёт одну дочернюю таблицу, изменения из неё немедленно видны в Card и наоборот. Не теряются данные при rename/move/delete link и при наличии двух открытых представлений. Проверить смешанную иерархию, selection и layout.

Верх карточки: название и тип, компактное краткое описание, заметный портрет, дальше вкладки и визуальный документ. Нет шаблона, aliases, tags, дублирующей группы характеристик, гигантской панели. Портрет: убрать поля/диалог подписи и описания, связанные свойства portrait payload и кнопку «…» рядом с изображением. Доступность сохранить через фиксированные доступные названия контролов, не через пользовательские alt/caption портрета. Пустая область изображения сама является кнопкой выбора изображения — плюс/placeholder. При наличии картинки удалить постоянные «Добавить/Заменить/Убрать портрет»; показать маленькую панель действий при наведении/фокусе: заменить (или щелчок по изображению), кадрировать, удалить (крестик/корзина в верхнем углу). Не дублировать действия в лишнем меню; keyboard/focus alternative, tooltip; не удалять оригинальный общий asset при снятии портрета.

Кадрирование в стиле соцсетей: отдельный диалог с видимой рамкой, затемнённой областью за ней, перемещением изображения мышью, масштабированием, превью, «Применить», «Отмена», «Сбросить»; исходная фотография не изменяется. Сохранять валидированную нормализованную область crop относительно ориентированного исходного изображения в единственном Portrait contract; корректно учитывать EXIF/пропорции, воспроизводить при смене размеров/DPI, сохранении и восстановлении. Не хранить случайный screenshot виджета. Использовать bounded thumbnails/asset путь; выбор картинки/кадрирование не создаёт лишних копий файла. При замене источника сбрасывать или явно пересчитывать crop. Изменения портрета всех наследующих размещений видны без повторного открытия.

Undo/Redo в редакторах — одинаковые иконки из существующего icon system (изогнутые стрелки), с подсказками и Ctrl+Z/Ctrl+Y, корректные enabled и фокус. Не создавать глобальные shortcuts, которые меняют чужой активный документ.

## D. Карта: блокирующий дефект сетки и отдельный редактор
**Linear:** ARU-77, ARU-81, ARU-70, ARU-63. Пункты 13–17.

### D1. Сетка
Скриншот `references/grid-offset.png`: фон находится в центре, сетка такого же размера сдвинута вправо и вниз. Это регрессия, визуальный дефект, блокирующий приёмку. В `GridLayer.paint` в f277095 используется `painter.deviceTransform()` и затем `resetTransform()`; это первая проверяемая гипотеза, а не установленная причина. Воспроизвести на реальном QGraphicsView: маленькая прямоугольная карта, viewport больше карты, ненулевой pan/scroll/viewport origin, fitInView, дробный zoom/DPR. Система координат фона, grid, token и placed objects общая (map/world coords); корректно преобразовать один раз из неё в viewport/device. Не применять компенсацию константой «на глаз», не смешивать логические и физические пиксели. Сетка клипуется к границе карты, соответствует grid offset в координатах карты, не двигается относительно фона при pan/zoom/resize/drag. Линии тонкие и визуально одинаковые, без двойного прохода/ореолов; на дальнем масштабе LOD прореживает линии, не утолщает их. Сохранить производительность и тайлы libvips. Добавить raster regression: сравнить фактические координаты линий и границы известного фона при translation, разных DPR и zoom; проверить несколько pan/resize и движение токена. Старые тесты толщины без сопоставления с фоном недостаточны.

Убрать «Прилипание к центрам клеток» целиком — UI, MapGrid.snap, snap_point и вызовы, codec/тесты/подсказки. Токены двигаются свободно, footprint по-прежнему в клетках (1×1 default), наследование Card и размеры не ломать. Не удалять offset/size/opacity/color сетки. Убрать кнопку «Название» из toolbar карты, оставить переименование через контекстное меню сущности. Undo/Redo стрелками. Вынести редактирование слоёв и объектов из обычной карты.

### D2. Отдельный Map Editor
Зафиксируй в ADR: владелец отклонил встроенный режим редактора карты итерации 4; этот интерфейс не считается целевым или принятым. Вместо «включить режим» открывай отдельное окно `Редактор карты · <название>` из контекстного действия/компактной кнопки обычной карты. Это полноценное dockable/floating окно Qt ADS с отдельным стабильным WindowManager key на map UUID (один editor на карту); карта как документ может быть открыта рядом. Не создавать второй Map Entity, копию карты, дублирующий writer и отдельный независимый Undo канона. Общие MapDocument/ModuleSession/asset repository; renderer/pyramid/cache переиспользуются, каждый view имеет собственную camera/selection; синхронные адресные уведомления о правках. Обычный Map Viewer предназначен для проведения игры: фон, сетка, tokens, pan/zoom, fit, open Card; без выпадающего редактирования слоёв и режима создания декора. Редактор — для строительства: отдельный canvas, компактные группы инструментов selection/pan/place/transform/delete и undo/redo, список слоёв (название, visibility, порядок, active), палитра локальных assets (выбрать/импортировать/ref), свойства выделенного объекта, сохранение через общую сессию. Расположение инструментов логично для работы (слева инструменты/слои, центр canvas, справа контекстные свойства либо максимально близкий native layout). Манипуляции move/resize/rotation/delete, layer visibility/order и выбор ресурса доступны прямо в редакторе, не только через длинную цепочку диалогов; внятное состояние выделения, отмена жеста Escape. Использовать текущие MapLayer/PlacedAssetObject, не превращать текстуры/дома в Card-токены. Удалить старый edit_mode UI и неиспользуемые paths после переноса поведения. Нужен фундамент для дорог, домов, стен, но сами vector drawing/walls/light/fog/pathfinding, combat и отдельный Big Map вне этой итерации.

**Приёмка:** open viewer, открыть editor, повторно открыть editor (focus существующего), разместить asset на слое, drag/resize/rotate, hide/show, delete/undo; изменения видны в viewer. Проверить независимые камеры, close/float/redock/layout restore, удаление карты/закрытие мира завершают оба окна, сохранение/backup/reopen. Токены не перемещаются случайно при редактировании объектов. Не считать D завершённым по старому тесту GridLayer без live viewport.

## E. Таблицы как полноценные документы и представления
**Linear:** ARU-78, ARU-83. Пункты 18–20.

Убрать из toolbar «Выше», «Ниже», стрелки перемещения колонок, «Выбрать случайную строку» и специфичную панель результата/копирование случайного результата. Нормальная таблица: после последнего заголовка колонки компактный [+] (Column 1 | Column 2 | [+]), после последнего номера строки [+] для новой строки; в пустой таблице тоже доступны оба действия. Header controls не являются fake rows/columns/cells и не попадают в persistence, selection, TSV, поиск. Клик [+] создаёт реальный столбец (название/тип) или строку, выделяет/фокусирует новую ячейку. Корректно при узком dock, scroll, горизонтальном/вертикальном заголовке, смене размера столбцов, отсутствии строк/столбцов. Undo/Redo для таблиц не обещать, если в текущем контракте нет; сохранять существующие безопасные операции и отказ invalid input.

## Политика экономного тестирования (обязательная)

- Не запускать полный pytest, Ruff по всему репозиторию, тяжёлые benchmarks или PyInstaller после каждой строки/мелкой правки. Использовать уже имеющийся зелёный CI как baseline, если checkout совпадает и среда исправна; не повторять baseline без причины. Проверить новый HEAD, CI и зависимости один раз.
- Группировать взаимосвязанные изменения. Во время разработки использовать чтение кода, локальный syntax/lint по изменённым файлам и точечные тесты, когда они нужны для диагностики. После завершённого блока — целевая группа затронутых domain/session/UI/storage тестов. При падении сначала самый узкий воспроизводящий сценарий, затем смежная группа. Не переписывать тесты для создания видимости зелёного результата; удалять лишь проверки намеренно отменённого контракта и заменять проверками нового. Критичные изменения схемы/общей модели/жизненного цикла окон/сохранения оправдывают один интеграционный gate на соответствующей границе (например, после A+B+E/F), а не серию одинаковых прогонов без изменений.
- Один итоговый полный `python -m pytest`, `python -m ruff check .`, `python -m pip check`, `git diff --check` в locked environment после завершения всех блоков. Устранить обнаруженные ошибки, сделать целевые reruns; если итоговый код существенно изменился, повторить общий gate. Тяжёлые benchmark/Windows frozen build делать после стабилизации (повтор только при реальной необходимости source/binary parity). Сборка и frozen self-test — действующими скриптами проекта, проверить native зависимости, лицензионную комплектность и совпадение исходников с дистрибутивом. Не изменять runtime lock без необходимости.
- По возможности реальные Windows GUI captures/accessibility, сценарии pan/zoom/drag, crop, resize, dock/floating, table headers, Tab/keyboard. Если capture недоступен — честно отмечать «Не проверено»; не подменять реальную ручную приёмку синтетическими снимками или количеством прошедших тестов. Clean Windows без Python остаётся ARU-64, не закрывать по запуску на машине с Python.
