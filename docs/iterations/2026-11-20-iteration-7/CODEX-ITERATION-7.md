## E. Туман войны (ручной) — ARU-86, ARU-85, ARU-77

Новые возможности 2–3. В обычном Map Viewer — icon-only действие «Туман войны». По нажатию появляется компактная контекстная панель; повторное нажатие скрывает панель, не отключает сам туман игрокам. Инструменты:
- Кисть: покрыть (скрыть) участок свободным мазком, регулируемый размер в координатах карты.
- Ластик: раскрыть участок, вычитая мазок из существующих областей, независимо от того, как они были созданы.
- Многоугольник (перо по вершинам): щелчки задают границы, превью последнего сегмента, замыкание кликом по первой вершине или Enter; Escape — отмена. Минимум 3 различных точки, проверка самопересечений/degenerate polygon; не сохранять незавершённые формы.
- Выбор: выделение созданной фигуры, Delete или icon-only delete удаляет выбранную область. Перекрывающиеся области остаются скрытыми, пока их тоже не стерли/удалили. Предусмотреть выбор мышью по всему видимому фрагменту, согласовать overlap hit test и selection outline.
- Undo/Redo — существующий Map undo stack. Один завершённый мазок/ластик/фигура/удаление = одна команда. Не создавать undo entry на каждую точку. Изменения fog не перемещают токены или объекты. Space для pan при рисовании, Escape отменяет незавершённый жест, вернуть предыдущее состояние. Стрелки остаются icon-only с tooltip.

### Модель, хранение и отрисовка

Предлагаемая схема: канонические `FogRegion(id, geometry)`/`FogState` в текущем Map payload, координаты в image/world-space, устойчивые UUID и явно определённая семантика union/subtract. Кисть создаёт область, polygon — отдельную область, ластик вычитает геометрию из всех пересечённых областей (дырки и разделённые компоненты сохраняются); ID фигуры остаётся устойчивым после вычитания, пустые области очищаются. При удалении — удалить только выбранную область и пересчитать объединение. Инженер может выбрать эквивалентное более подходящее представление, но оно обязано поддерживать эти операции, сериализацию и выбор фигуры. Не строить собственный ненужный GIS engine; проверить возможности текущего Qt для геометрии, отделить канонические числа от GUI объектов и не допускать Qt в domain. Не хранить QPixmap/огромную маску полной карты, не кодировать картинку целиком в SQLite. Bounded geometry/brush sample simplification, finite coordinate validation, ограничение сложности с понятным сообщением, spatial/visible culling при измеряемой необходимости. Правило границ согласовать с существующим world bounds, чтобы весь показанный игровой участок можно было закрыть, включая объекты, если карта допускает выход за фон. Не вводить глобальный произвольный пиксельный лимит.

- Ведущий видит полупрозрачный чёрный туман (предложенный default 50%, только visual GM role) и область редактирования. Игроки видят полностью непрозрачный чёрный слой поверх всех видимых тайлов, сетки, объектов и токенов; скрытая часть токена тоже маскируется. Не переносить GM alpha на player. Растеризация не должна давать светящиеся швы/дыры на границах, при clipping и DPR. Использовать один и тот же geometry snapshot, разную presentation alpha/overlays. Не показывать hidden GM annotations. Начальная карта не закрыта туманом; явное рисование закрывает области. Не добавлять автоматический LOS, свет, индивидуальную видимость игроков и rules engine.
- Рисование в процессе может обновлять preview у GM. На player не показывать временное раскрытие незавершённым ластиком или фигурой: раскрытие только при commit; закрывающий preview допустимо показывать сразу без раскрытия ранее скрытых данных. Escape отменяет provisional data. При обновлении snapshots игроки видят согласованную версию карты и fog; никаких промежуточных кадров без fog. Движение токена через скрытую зону не раскрывает её автоматически.
- Сохранить fog в SQLite с новым текущим payload contract и строгой валидацией при load/save; undo/redo, backup/restore, reopen, map delete; не писать в кеш как единственный источник истины. Схема актуального формата и ADR обновляются. Отдельные presenter camera/UI состояния не являются игровыми данными.

Проверки E: add multiple brush strokes/polygon, erase through overlap/hole/split, select/delete one, invalid geometry, Esc, undo/redo, save/reopen/backup/restore; toggle tool panel doesn't change fog; draw/erase at multiple zooms with nonzero pan and DPR; actual render test samples pixels under hidden token/object/grid and revealed areas; first frame after load and generation switch; GM alpha vs player opaque; 233MP-like large map, two windows, realistic geometry load, bounded memory and UI responsiveness. ## F. Дефект из независимого аудита — ARU-46, ARU-78

В итерации 6 подтверждён дефект FieldEdits/TablesService: два редактора одного поля, второй записывает B, первый получает conflict draft A; после reopening и завершения без изменений A молча перезаписывает B. Воспроизвести на текущем коде; не считать исправленным только из-за разделения сервисов.

Нужен явный статус конфликта, сохраняющий новый канон и пользовательский черновик. Reopen/blur/unchanged commit/flush/Ctrl+S не превращают draft в authoritative value. Дать понятные действия «Использовать сохранённое» и «Применить мой вариант»; применение проверяет текущую версию/значение, при новой конкурентной правке повторное разрешение, не silent last-writer-wins. Escape/close/discard согласованы с текущим UX. Invalid/conflicting draft одного поля не блокирует autosave других валидных изменений. Не откатывать уже исправленный continuous typing и не возвращать broad refresh. Проверки обоих сервисов и mixed embedded/standalone, оба порядка передачи фокуса, повторный вход без редактирования, активный ввод, background save ACK, close/reopen, conflict resolution with third edit.
